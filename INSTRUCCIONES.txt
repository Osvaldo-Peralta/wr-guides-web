PASOS (en tu máquina)
  0. Prerrequisito: wr-guides-api v0.3.2 ya desplegada ✓ (este paquete NO toca
     el repo de la API).
  1. Descomprimí el zip DENTRO de tu clon, sobreescribiendo:
       cd "<tu-clon>/wr-guides-web"
       unzip -o ruta/al/wr-guides-web-fase6-7-jinx.zip
  2. Instalá la dependencia nueva:
       npm install
  3. (Opcional, recomendado) build de control:
       npm run build          → 22 páginas, sin errores de tipos
  4. Commit + push (Vercel redeploya solo):
       git add -A
       git commit -m "Fases 6-7: sync lab→web automático + Vercel Analytics + tema Jinx"
       git push
  5. VERCEL — activar Web Analytics (Fase 7):
       Proyecto wr-guides-web → pestaña ANALYTICS → "Enable Web Analytics".
       Sin este paso el sitio funciona igual (el código es no-op); con él, en
       ~24 h ves páginas más visitadas, países, dispositivos y el evento
       guide_like. Plan Hobby: 2.5K eventos/mes incluidos.
  6. (RECOMENDADO) Secret para la re-siembra de la API tras cada sync:
       GitHub → repo wr-guides-web → Settings → Secrets and variables → Actions
       → New repository secret → Name: ADMIN_TOKEN
       Value: el MISMO valor que la env var ADMIN_TOKEN del proyecto API en Vercel.
       Sin el secret el sync de contenido funciona igual; solo que una guía
       NUEVA quedaría sin stats hasta un seed manual
       (cd ../wr-guides-api && WR_API=https://wr-guides-api.vercel.app npm run seed).
  7. Probá la Action sin esperar al cron:
       GitHub → wr-guides-web → Actions → "Sync lab → web" → Run workflow.
       (El contenido 06-OCT ya viene en este paquete, así que la primera
       corrida probablemente diga "Sin cambios" — es el resultado correcto.)
  8. Tema: abrí https://wr-guides-web.vercel.app → abre con el tema JINX.
     El botón 🎨 del header alterna con el clásico y la elección queda guardada
     en tu navegador. Para que el clásico sea el default global: README §
     "Tema visual" (un string en layout.tsx).

NOTAS IMPORTANTES
  · NEXT_PUBLIC_API_URL en Vercel: creala como variable NORMAL — Vercel bloquea
    el modo "Sensitive" para NEXT_PUBLIC_* por diseño (lo sensible no puede
    incrustarse en el JS del navegador; una URL pública no es secreto). La
    variable API_URL que cargaste NO la lee el cliente: es inofensiva pero
    inútil; podés borrarla sin impacto (el fallback hardcodeado de lib/api.ts
    ya apunta a producción). Detalles en .env.example y README.
  · El like huérfano de las pruebas de verificación (Cho'Gath jungla, +1) se
    limpia con este SQL en Supabase → SQL Editor (afecta exactamente 1 fila):
